# サイトの現在地

何を載せるかの現在地。経緯は書かず、決まったことと足りないものだけを置く。
見せ方は [design.md](design.md)、実装は [README](../README.md)。

## 目的

写真作品を見せ、撮影の依頼を受ける。海外からの展示の依頼も受けたい。エンジニアの仕事は当面受けない。
ただし、エンジニアであることと、このサイトを自分で作ったことは見せる。
About の Subject に書く Architecture は、Photos では street か abstract に振り分ける（カテゴリを分けない）。

## ページ

| ページ | 役割 | 状態 |
|---|---|---|
| `/` | 粒子の hero と導線 | 動いている |
| `/photos/:category` | 作品。street / abstract / color を URL（`/photos/street` など）で切り替え。`/photos` は street へ転送。段組の一覧。クリックでその場で全幅に広がり、もう一度押すと戻る。広げられるのは 1 枚で、別の写真を押すと切り替わる | 実装済み |
| `/works` | 撮影の依頼の実績（公演・講演・ポートレート）。ジャンルの見出しを立てず 1 本の流れで並べ、案件の最初の写真に種類と説明の 1 行を添える。写真の追加と説明はサイトの上で編集する | 仕組みは実装済み。写真と説明（仮）を入れる |
| `/about` | ステートメント・プロフィール・受賞・展示・掲載・リンク | 仮実装。ステートメントは本人の言葉に差し替える |
| `/contact` | 撮影の依頼。ジャンルは問わない。フォーム（名前・メール・内容）とメールで受ける | 実装済み |

ナビは固定表示で、左にロゴ（トップへ）、右に4項目（Photos / Works / About / Contact）。フッターも固定表示で、右に
Instagram / X のアイコン、左にそのページ固有の操作を置く。トップは hero の再生・停止と
次の写真までのプログレス。再生は常にランダムで、全部を表示し終えるまで同じ写真を出さない。プログレスは PC では再生操作の後ろに短く置き、スマホでは
フッターの上の線を使う。Photos はカテゴリの切り替え。
hero の写真の横（狭い画面では下）には番号のカレンダーを置く。

## 住所

mu826.com（Cloudflare で登録）。www と http は mu826.com の https へ転送する。stosto826.workers.dev も
同じ内容のまま開けておく。問い合わせのメールは hello@mu826.com で、Gmail へ転送する。フォームも Gmail へ届き、返信は Gmail から出す。

## 写真の管理

正本は R2 の manifest.json。hero と Photos の両方がこれを実行時に読む。
追加・入れ替え・並べ替え・カテゴリと hero の選択は、サイトの上で行う。`/admin`（Cloudflare Access で保護、
本人のメールのみ）でログインすると、Photos とトップに編集の操作が出る。変更は下書きにためて「公開」で反映する。
本番は R2・Access・Worker の secret まで設定済みで動いている。最初の移行は
`scripts/encode-photos.mjs` と `scripts/sync-photos.mjs` で済ませた。
