# サイト構成と内容

このサイトに何を載せるかを決めていくためのドキュメント。会話で決まったことをここに
書き足していく。**最終更新: 2026-09-11**

## 前提

**サイトの目的**: 写真作品を見せること、写真の撮影依頼を受けること、エンジニアと
しての仕事を見せること。

**2種類の読者がいる。**

| 読者 | 何を見に来るか | 求めるもの |
|---|---|---|
| 写真の依頼者・作品の鑑賞者 | 写真 | 大きく、速く、邪魔されずに見たい |
| エンジニア（採用・協業） | 技術的な成果物 | 何を作れる人かを知りたい |

この2つは求めるものが逆を向く。粒子ギミックはエンジニアには効くが、写真の鑑賞者に
とっては写真を壊すノイズになる。構成の判断はほぼ全部この緊張関係から出てくる。

## 決まったこと

**仕事を受ける（写真）。** 2026-09-07 確認。これにより、作品を見せるだけのサイトでは
なく、依頼につながる導線が必要になった。

**ナビゲーションは固定表示、4項目。** 2026-09-07 仮決定。

```
Photos   Works   About   Contact
```

- **固定表示にする理由**: 仕事を受けるので、どのページ・どのスクロール位置からも
  1クリックで連絡先に届く必要がある。
- **薄いガラスの帯にする。** 2026-09-09 に方針を変更した。以前は「帯は写真の上に
  常時ノイズとして乗る」として不採用にしていたが、hero を写真＋パネルの縦並びに
  変えた結果、**写真がナビの下に潜らなくなった**ので前提が消えた。
  `rgba(0,0,0,0.35)` + `backdrop-blur(14px)` + 下辺 1px の罫線。hero では下が地の色
  なので効果は見えず、スクロールして下のセクションが通るときだけ効く。
  なお `mix-blend-mode: difference` は中間グレーの面積が広い作品では文字が消えるので
  引き続き不採用。
- **`commission` は独立ページにせず Contact に統合。** 項目を増やすほど写真から視線が
  逸れる。依頼者にとっても「受ける仕事・流れ・料金・連絡先」が一箇所にあるほうがよい。
- hero の写真インデックス（右端中央）と右上ナビが縦に並ぶので、実装後に見え方を確認して
  必要ならインデックスの位置をずらす。


**hero は写真とコントロールパネルの2つを並べる。** 2026-09-10 決定。画面のアスペクト比で
横並び / 縦並びを切り替える（しきい値は固定値ではなく、写真が大きくなるほうを選ぶ）。
パネルは 7列のカレンダー状に番号を並べ、選択中を丸で囲む。丸は遷移の開始で次の番号へ動く。
上部に細いプログレスバーを置き、前の遷移の開始で 0、次の遷移の開始で 1 になる。

**hero の粒子はマウスと指に反応する。** 2026-09-11 実装。ポインタの移動速度に比例した力が
ポインタ起点でかかり、粒子は写真上の位置へバネで引き戻される。**干渉が止めば必ず元の写真に
戻る**ので、作品を壊したままにならない。暗い粒子ほど重く、触っても動きにくい。

**リポジトリは GitHub に登録済み（public）。** 2026-09-10。`git@github.com:satoshi826/mypage2026.git`

**個人作品と依頼実績は分ける。** 作品はモノクロの街・建築、シルエット中心の強い個人
スタイル。クライアントは「自分の案件に近い仕事」を見たいので、同じ場所に混ぜると
「この人に頼んだらどうなるか」を判断できなくなる。

## 構成案（ドラフト・未確定）

```
/              トップ — 粒子ヒーロー（2〜3枚）＋ 名前・肩書き・導線をテキストで
/photos        作品。効果なしの素直なビューア
/commission    撮影依頼 — 受ける仕事、実績、流れ、料金の目安
/works         エンジニアリング。粒子ギミックの技術解説もここ
/about         プロフィール、ステートメント、経歴
/contact       連絡先（commission に統合する可能性あり）
```

写真家のポートフォリオの定番は **Work / About / Contact の3項目**。項目を増やすほど
写真から視線が逸れるので、意図的に絞られている。上の案はそれに依頼と技術の2つを足した
形なので、増やしすぎていないか要検討。

### 各ページに載せるもの

**トップ** — 粒子ヒーロー。100svh の1画面で自動再生し、スクロールは遷移を操作しない
（2026-09-09 にスクロール駆動から変更）。写真はランダム順に巡回するので、枚数を増やしても
スクロール量は増えない。自動再生の ON/OFF と現在の枚数を示す UI を画面内に置く。
1画面ぶんで抜けられるので、写真を見に来た人も依頼者もすぐ下の導線に届く。

**photos** — シリーズ別かジャンル別かは未決（下記）。効果なし、大きく速いビューア。

**commission** — 撮影ジャンル、対応地域、流れ（相談→見積→撮影→納品）、納品形式と
枚数の目安、可能なら開始価格。「お問い合わせください」だけでは問い合わせは来ない。
金額を出すと問い合わせは減るが、話が通じる相手だけが来るので効率は上がる。

**works** — 粒子モーフの解説を置く。輝度ランク空間を経由して対応を取ると N 枚が任意順
で接続でき、誤差も蓄積しないという話は読み物として成立する。トップの実物へリンクする。

**about** — プロフィール写真、ステートメント、経歴（個展・掲載・受賞）。写真家のサイト
では About は自己紹介というより信用の材料。

## 決まっていないこと

**受ける撮影のジャンル。** ポートレート / イベント / 建築・空間 / 物撮り のどれか。
→ これが決まらないと `photos` の分け方（シリーズ別 or ジャンル別）と `commission` の
中身が決められない。**最優先で決めたい。**

**エンジニアの仕事も受けるのか。** 写真だけか両方か。
→ `works` が「実績」なのか「作品紹介」なのかが変わり、ナビでの扱いが変わる。

**トップに置く写真の枚数。** 実体は12枚で、見え方の確認のため mod で31枚に水増し中
（`src/hero/photos.ts` の `COUNT`）。以前あった「2〜3枚に絞る」方針は 2026-09-09 に撤回した。
**枚数が増えてもスケールする方式**（グリッドを VRAM とテクスチャ上限だけで決める、
アトラスを最小スロットで敷き詰める）にしたため、50枚程度までは構成を変えずに増やせる。
順序は実行時にランダムなので、`photos.ts` の並びが決めるのは番号表示と最初の1枚だけ。

> トップページは粒子ギミックの検証を兼ねた**仮実装**。レイアウトも構成も確定ではないので、
> これに引きずられずに設計してよい。

**ヒーローの表示アスペクト比。** 現在 3:2（写真そのまま）。16:9 などにするなら
`src/hero/table.ts` の `SOURCE_W` / `SOURCE_H` と写真の書き出しを揃えて変更する。

**デプロイ先。** mypage2025 は Cloudflare Workers 構成だった。静的出力ならどこでも
置けるので、方式が決まってから。

## 技術的な制約（構成の判断に効くもの）

- **canvas の中身は検索エンジンから見えない。** 仕事を受けるなら、名前・肩書き・
  活動地域・撮影ジャンルが実テキストとして存在する必要がある。粒子ヒーローだけの
  トップページは検索の材料がゼロ。
- **粒子ギミックは全写真を同一アスペクト比に揃える必要がある**（粒子集合を共有する
  ため）。現在 3:2。
- **モノクロ前提。** 輝度が1次元で全順序が付くことが対応付けの根拠。カラー写真を
  混ぜても動くが、対応の意味が薄れる。
- **初期表示。** 現在は全枚数の取得とテーブル構築が終わるまで何も描かない。トップに
  置くなら1枚目ができた時点で描き始める順序に変えたい。
- **VRAM は31枚で約 119MB**（アトラス 99MB + 干渉の状態と深度 19.5MB）。枚数を増やすと
  グリッドが自動で下がるので上限には当たらないが、**モバイル実機では未測定**。
  ここが厳しければ粒子グリッドを落とす判断が要る。
- **干渉が有効なあいだ毎フレーム描く。** 81万粒子 × 2パス（状態の更新と描画）。
  hero が画面外に出れば止まる。フレーム時間は未測定。
- **ビルドに Node 20.19+ が要る。** Vite 8 / oxlint / oxfmt が揃ってこのラインを
  要求する。デプロイ先を選ぶときはビルドイメージの Node が満たすか確認する。

## 実装済みのページ骨組み

ナビとルーティングは通っている。中身は以下の状態。

| ページ | 状態 |
|---|---|
| `/` | hero（仮実装）＋ 名前・肩書き・導線のテキスト |
| `/photos` | フラットなグリッド。hero と同じ一覧を流用した仮実装で、鑑賞用の解像度がない。分け方も未決 |
| `/works` | 粒子モーフの説明が1件のみ |
| `/about` | 見出しのみ。ステートメントと経歴が必要 |
| `/contact` | 見出しのみ。撮影ジャンルが決まらないと書けない |

`src/app/routes.ts` がルート定義の唯一の出典。ナビもプリレンダも title / description も
ここを見る。ページを足すときはここに追加する。
